Codex 오래된 세션 수동 정리

실행 환경: Node.js 22.16 이상인 22.x, 23.8 이상인 23.x 또는 24 이상.
manual.cmd와 repair-list.cmd는 시작할 때 SQLite 백업 기능을 공통으로 확인하며,
지원하지 않는 환경에서는 세션 삭제나 목록 변경 전에 필요한 버전을 안내합니다.

정책: 마지막 대화, 최근 활동, 로그 수정 시각이 모두 7일보다 오래된
로컬 Codex 세션을 삭제합니다. 보관된 세션도 포함합니다.
고정 세션, 실행 중이거나 로드된 세션, 현재 관리 대화는 제외합니다.
자식 중 하나라도 보호 대상이면 부모와 자식 전체를 남깁니다.
삭제 직전에 조건과 고정 상태를 다시 확인합니다.
프로젝트 원본이나 Git 저장소를 삭제하는 도구가 아닙니다.

수동 삭제:
1. Codex 앱과 Codex CLI/IDE 세션을 모두 종료합니다.
2. manual.cmd를 더블클릭합니다.
3. 대상 수와 reports의 상세 목록을 확인합니다.
4. DELETE 뒤에 표시된 대상 수를 입력하면 확인한 세션 묶음만 영구 삭제합니다.
   Enter만 누르거나 창을 닫으면 취소됩니다.
5. 삭제한 세션의 대화 목록 항목도 백업 후 정리합니다.
6. 완료될 때까지 Codex를 닫아 두고, 완료 후 다시 실행합니다.
일부 삭제나 마지막 검증이 실패해도 삭제에 성공한 세션의 목록은 정리하며,
실패한 그룹은 보존합니다. 원래 실패는 결과 보고서와 종료 상태에 남습니다.
고정 상태는 현재 데스크탑 앱의 고정 목록을 기준으로 읽습니다.
이전 버전에서 옮겨온 고정 이력은 현재 고정으로 집계하지 않습니다.
데스크탑 고정 목록이 없는 환경에서는 최신 상태 DB를 사용합니다.
미리보기와 삭제 직전 재검증은 같은 고정 정보 선택 정책을 사용합니다.
데스크탑 목록이 있으면 DB나 응답에 남은 이전 고정 값으로 다시 보호하지 않습니다.
Codex가 실행 중이면 수동 실행을 중단합니다.
차단 메시지에 남아 있는 Codex 프로세스의 PID가 표시됩니다.
삭제 중 도구의 app-server가 종료되거나 응답 연결이 끊기면 후속 요청을 기다리지 않고 작업을 중단합니다.
진행 중인 묶음은 실패, 아직 시작하지 않은 묶음은 미처리로 보고서에 남깁니다.
이미 성공을 확인한 묶음의 대화 목록 정리는 계속하고 원래 종료 오류를 보고합니다.
응답 전에 연결이 끊겨 삭제 여부를 확인하지 못한 묶음은 성공으로 간주하지 않습니다.

이미 삭제했는데 대화 목록에 항목이 남은 경우:
1. Codex 앱, VS Code 등 Codex 확장이 실행 중인 IDE와 CLI를 종료합니다.
2. repair-list.cmd를 더블클릭합니다.
3. 표시된 CLEAN 명령을 입력하면 목록만 정리합니다. Enter는 취소합니다.
과거 삭제 보고서에 성공으로 기록된 세션 중 로그(.jsonl/.jsonl.zst)가 없고
현재 상태 DB에도 없는 ID만 대상입니다. 다른 호스트의 목록은 보존합니다.
목록 DB 백업과 결과는 reports\catalog-backups에 저장됩니다.
변경 없이 확인: node repair-list.mjs --preview (Codex 실행 중에도 확인 가능)
손상되었거나 읽을 수 없는 과거 보고서는 경로와 사유를 표시하고 건너뜁니다.
보고서의 UUID, 저장 위치, 확장자, 파일명 등 내용 오류도 이 단계에서 제외합니다.
정상 보고서의 처리는 계속하며, 마지막에도 건너뛴 보고서 수를 표시합니다.
건너뛴 보고서에만 기록된 항목은 해당 보고서를 복구한 뒤 다시 정리해야 합니다.
현재 로그의 파일 상태나 접근 권한, 상태 DB를 확인할 수 없으면 안전을 위해
전체 작업을 중단합니다. 로그 상태 오류에는 원본 보고서 경로도 표시합니다.

수동 확인: preview.cmd를 더블클릭하면 삭제 없이 대상과 예상 용량만 표시합니다.
화면 출력: 전체 수, 삭제 대상, 제외 사유, 예상 로그 용량을 한글로 표시합니다.
압축된 로그(.jsonl.zst)도 로그 파일로 보고 예상 용량에 포함합니다.
로그가 이미 없는 대상은 DB 항목만 정리하며, 디스크 용량 확보 효과는 거의 없습니다.
세부 결과: reports 폴더의 TXT 파일(읽기용)과 JSON 파일(원본)
프로그램 연동용 JSON 출력: node cleanup.mjs --json
기준 일수: config.json의 days (7 이상, 기본값 7)
추가 제외: config.json의 protectedIds

삭제는 Codex app-server의 thread/delete를 사용하며 영구 삭제입니다.
세션 로그와 상태 DB는 직접 지우지 않습니다. 로그가 이미 없는 항목은 메타데이터만 정리됩니다.
manual.cmd는 삭제 완료 후 앱의 별도 목록 DB(codex.db, codex-dev.db)에서
해당 로컬 ID만 제거하고 목록 버전 및 진행 중인 목록 스캔의 삭제 기록을 갱신합니다.
cleanup.mjs --apply만 직접 실행한 경우에는 repair-list.cmd로 목록을 별도 정리합니다.
공식 API: https://learn.chatgpt.com/docs/app-server#delete-a-thread
