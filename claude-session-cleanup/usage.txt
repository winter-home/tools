Claude Code 오래된 로컬 세션 수동 정리

실행 환경: Windows, Node.js 22 이상. 추가 npm 패키지나 SQLite는 필요하지 않습니다.

현재 지원 범위
- Claude 앱 데이터가 없는 CLI 전용 환경은 수동 정리를 지원합니다.
- Claude 앱의 고정 원본(IndexedDB)을 직접 검증하는 기능은 아직 없습니다.
  앱 데이터가 발견되면 JSON 복제본이 정상이어도 실제 삭제를 차단합니다.
  해당 환경에서는 미리보기만 지원합니다. 복제본만으로 고정 없음/검증 완료라고 판정하지 않습니다.
- 앱 데이터 폴더를 숨기거나 목록에서 빼서 차단을 우회하지 마세요.
- 앱 설정 파일만 있거나 내용이 비어 있어도 '앱 데이터 없음'으로 간주하지 않습니다.
  알려진 파일명과 무관하게, 발견/지정한 앱 데이터 폴더에 내용이 있으면 미확인으로 유지합니다.
  비표준 설정 이름이나 Partitions 등 다른 하위 저장 구조도 이 정책에 포함됩니다.
  고정 정보 수집 결과는 앱 데이터 없음/원본 미확인으로 구분합니다.
  원본 검증됨 상태는 실제 원본을 검증한 경우에만 허용하며 현재 수집기는 이 상태를 만들지 않습니다.

정리 기준
- 마지막 대화, 관련 파일 수정 시각, 앱의 최근 활동 시각이 모두 7일보다 오래된 세션.
- config.json의 days는 7 이상이며 기본값은 7입니다.
- 같은 대화 ID가 여러 프로젝트에 있으면 한 묶음으로 판정합니다.
- 메인 로그는 일반 파일이어야 하며, 삭제 후보로 인정하기 전에 각 메인 로그의 내용을 검증합니다.
  UUID.jsonl 이름의 디렉터리는 세션으로 취급하지 않습니다. 메인 로그 없이 남은 부속 자료도 삭제하지 않습니다.
- 부모와 하위 에이전트 로그, 별도 도구 결과, 파일 수정 이력도 함께 확인합니다.
- 고정 대화와 protectedIds에 지정한 대화는 제외합니다.
- 손상된 로그, 링크/junction, 활동 시각을 검증할 수 없는 세션은 보존합니다.
- MCP 작업 상태가 남은 세션도 보존합니다.

미리보기 (삭제 없음)
1. preview.cmd를 실행합니다. Claude가 실행 중이어도 조회할 수 있습니다.
2. 대상 수, 용량, 제외 사유와 reports의 TXT/JSON 상세 목록을 확인합니다.
   고정 원본 미검증 경고가 있으면 후보 수는 참고용이며 실제 삭제는 허용하지 않습니다.
   빈 설정, 손상된 JSON, 구형 형식, 연결 정보가 없는 고정 ID는 경고와 잠정 후보를 표시합니다.
   경로 이탈, 링크/junction, 파일 접근 오류는 계속 전체 조회를 중단합니다.
   허용 루트 위의 부모 경로도 볼륨 루트부터 확인합니다. 설정한 저장 위치의 부모가 링크인 경우도 중단합니다.
   세션 파일에서도 같은 정책을 적용합니다. 손상된 로그 내용만 해당 세션의 제외 사유로 처리합니다.
   실행 중인 Claude가 파일을 바꾸면 실제 수동 실행 결과는 달라질 수 있습니다.
   JSON 출력: node cleanup.mjs --json

수동 삭제 (사용자가 나중에 직접 실행할 기능)
1. 트레이의 Claude 앱, Claude Code CLI와 Claude 확장이 실행 중인 IDE를 종료합니다.
2. manual.cmd를 실행합니다. 남아 있는 Claude 프로세스가 있으면 PID를 표시하고 중단합니다.
3. 표시된 대상과 상세 보고서를 확인합니다.
4. DELETE 뒤에 표시된 세션 수를 입력해야 실행합니다. Enter는 취소합니다.
5. 확인한 대상만 다시 검증하고, 압축 백업을 완료한 뒤 삭제합니다.
   새로 고정되거나 파일이 변경된 대상, 확인 후 새로 생긴 대상은 삭제하지 않습니다.
6. 완료될 때까지 Claude를 닫아 두세요. 결과는 reports의 TXT/JSON에 남습니다.
   중간 실패에도 결과 요약과 보고서 경로를 출력하고 실패 종료 상태를 유지합니다.
   확인 입력 후 설정을 다시 읽지 못해도 승인 대상 전체를 미처리 결과로 보고합니다.
   로그와 로컬 인덱스를 다시 읽어 삭제 ID가 사라졌는지 확인한 뒤 성공으로 기록합니다.
   항목이 남거나 검증 조회가 실패하면 삭제 성공으로 기록하지 않습니다.
   cleanup.mjs에 --apply를 주는 직접 삭제는 지원하지 않습니다.

고정 항목 보호
- Claude 앱 설정의 preferences.epitaxyPrefs.starred-local-code-sessions를 추가 보호 신호로 읽습니다.
- 앱의 local_<uuid>와 cliSessionId를 연결합니다. 두 ID가 다르므로 단순 비교하지 않습니다.
- 앱 ID는 문자열 UUID로만 해석하고 대소문자를 정규화합니다.
  배열·숫자·null 등 잘못된 타입은 형식 경고로 남기며 잠정 조회는 계속하고 실제 삭제는 차단합니다.
- 이전 dframe-local-slice.pinnedOrder와 메타데이터의 isStarred/isPinned도 보호에 합칩니다.
  따라서 앱에서 고정을 해제한 항목도 예전 표시가 남아 있으면 계속 보호될 수 있습니다.
- 고정 목록의 형식 오류는 원소별로 경고를 남깁니다. 잘못된 값 뒤의 정상 ID도 계속 수집합니다.
  현재 목록 자체가 잘못됐어도 legacy 목록은 독립적으로 처리합니다.
- 고정 목록을 해석할 수 없거나 고정 ID의 실제 대화를 찾을 수 없으면 삭제를 중단합니다.
  이런 형식/연결 오류는 미리보기에서는 경고로 남기고 조회를 계속합니다.
- JSON 키가 존재한다는 이유로 IndexedDB 원본을 검증한 것으로 처리하지 않습니다.
- 고정된 세션 그룹의 포함 대화를 검증할 수 없는 경우에도 중단합니다.
- 앱 고정 상태를 확인할 수 없는 환경의 desktop/Cowork 로그는 삭제 대상에서 제외합니다.
- CLI/IDE에 있는 별도 확장 프로그램의 고정 기능은 지원하지 않습니다.
  이런 항목은 protectedIds에 실제 대화 UUID를 추가해 보호하세요.

저장 위치
- 기본: %USERPROFILE%\.claude. CLAUDE_CONFIG_DIR가 있으면 해당 경로를 사용합니다.
- 앱: %APPDATA%\Claude, %LOCALAPPDATA%\Claude-Data의 하위 데이터 폴더,
  MSIX Packages\Claude_*\LocalCache\Roaming\Claude 및 Claude-3p를 자동으로 확인합니다.
- 다른 앱 데이터 위치는 config.json의 desktopDataDirs에 절대 경로로 추가하세요.
  고정 상태 확인을 위해 실제로 사용하는 앱의 모든 데이터 위치가 포함되어야 합니다.

삭제하는 범위
- projects/<프로젝트>/<대화 UUID>.jsonl과 해당 UUID의 세션 부속 폴더.
- 같은 UUID의 orphaned/superseded 로그, file-history, session-env, debug/<UUID>.txt.
- sessions-index.json의 일치하는 항목. 앱 세션 메타데이터는 읽기 전용으로 보존합니다.
- 인덱스의 다른 항목과 이미 로그가 없는 과거 항목은 그대로 둡니다.
  인덱스 전체가 아닌 실제 대화 파일을 기준으로 대상을 찾습니다.
- 프로젝트 원본, Git 저장소, memory, plans, 설정, 인증 정보는 삭제하지 않습니다.
- history.jsonl의 입력 이력은 기본 보존합니다. 전체 사용량 통계도 보존합니다.
- 빈 세션 폴더가 남을 수 있습니다. 폴더 전체를 재귀 삭제하지 않습니다.
- Claude 웹/클라우드 세션은 삭제하지 않습니다. 앱/IDE의 별도 캐시 목록까지
  동기화하는 기능은 없으므로 재실행 후 별도 화면에 항목이 남을 수 있습니다.

입력 이력 선택 옵션
- config.json의 removePromptHistory 기본값은 false입니다.
- true로 바꾸면 승인된 세션 중 로그 삭제를 완료하고 잔존 파일이 없는 ID의 입력 이력만 정리합니다.
- 보호/최근 활동/변경 때문에 제외된 ID와 일부 삭제에 실패한 ID의 이력은 보존합니다.
- 입력 이력을 먼저 검증하고 공유 백업을 완료한 후 세션 삭제를 시작합니다.
  손상된 입력 이력이나 백업 실패가 있으면 삭제하지 않습니다.
- 다른 ID의 줄과 sessionId가 없는 과거 형식의 줄은 원본 바이트를 보존합니다.
- 미리보기 이후 옵션이 바뀌면 다시 확인해야 합니다.

백업과 오류 복구
- reports/backups/<실행 ID>/<대화 UUID>/에 파일별 .gz와 manifest.json을 저장합니다.
- 인덱스와 선택한 입력 이력은 같은 실행 ID의 shared/에 한 번만 백업합니다.
- manifest.json에는 원래 파일 경로와 압축 백업 경로가 대응되어 있습니다.
- 복구할 때 Claude를 종료하고 .gz를 풀어 해당 원래 경로로 되돌리세요.
  현재 파일이 있는 경로를 덮어쓰지 말고 먼저 확인하세요.
  sessions-index.json 백업은 당시 전체 내용이므로 통째로 덮어쓰면 이후 항목을 잃을 수 있습니다.
  필요한 항목만 병합하세요. 앱 설정의 고정 목록은 이 도구가 수정하지 않습니다.
- 일부 파일 삭제 실패 시 즉시 중단하고 삭제한 파일 목록과 복구 위치를 보고서에 남깁니다.
  이후 새 세션 삭제는 시작하지 않으며, 앞서 완료한 그룹의 공유 메타데이터는 마저 정리/검증합니다.
  자동으로 원본을 덮어쓰는 롤백은 수행하지 않습니다.
- 승인 ID별 최종 결과는 삭제/실패/건너뜀 중 하나에만 집계합니다.
  준비/공유 백업 실패로 시작하지 못한 대상과 이전 오류로 남은 대상도 미처리 사유를 남깁니다.
  최종 보고서의 세 결과 수 합계는 승인 수와 일치하며 JSON의 outcomes에서 ID별 결과를 볼 수 있습니다.
- 승인 대상 목록과 개수/용량은 처음 확인한 범위를 유지합니다.
  최신 조회 결과는 revalidation에 참고 정보로 따로 남기며 새 미승인 ID를 대상 목록에 넣지 않습니다.
- 파일별 삭제 결과는 reports/*-progress.jsonl에 누적 기록합니다.
  전체 TXT/JSON 보고서는 시작과 종료/실패 시 작성합니다.
  비정상 종료 시 최종 보고서가 오래된 상태일 수 있으므로 journal과 백업 manifest도 확인하세요.
- 압축 백업을 보관하므로 실제 확보 용량은 원본 용량에서 백업 용량을 뺀 값입니다.
  백업 실패나 공간 부족이 발생하면 해당 세션의 삭제를 시작하지 않습니다.
- 비정상 종료로 .claude/.session-cleanup.lock이 남으면 모든 정리 프로세스를 종료하고
  보고서/백업을 확인한 후 해당 잠금 파일만 제거하세요. 자동으로 잠금을 해제하지 않습니다.

검증: node --test claude-session-cleanup/cleanup.test.mjs (저장소 루트에서 실행)
테스트는 운영 세션과 분리된 임시 디렉터리만 생성/삭제합니다.
이 도구는 Claude CLI를 실행하지 않으므로 Claude 자체의 자동 정리도 유발하지 않습니다.
